# 中文代码审查：检查项与决策树

本文件是 `cn-code-review` 的配套依据库，固化各语言高发检查项、严重度规范和不表演性同意的决策树。

## 一、四阶段时间分配（参考）

| 阶段 | 关注点 | 建议精力 |
|---|---|---|
| 上下文 | 改动意图、范围、测试 | 10% |
| 高层 | 架构、正确性、安全、性能 | 40% |
| 逐行 | 具体实现、语言陷阱 | 40% |
| 总结 | 分组、结论、冲突摆出 | 10% |

别在快速扫读和无限抠格式两头浪费时间，重点放在实际分析。

## 二、严重度标记规范

- `[BLOCK]` 必须改：正确性问题、安全漏洞、破坏现有功能、缺测试导致无法验证
- `[SUGGEST]` 建议改：可读性、可维护性、轻微性能退化、命名不清
- `[NIT]` 吹毛求疵：格式、个人口味、无功能影响的偏好

输出格式示例：

```
[BLOCK] 用户删除后订单状态没回滚，会留下脏数据。建议在事务里补 rollback。
[SUGGEST] 这个函数 80 行，建议拆成校验/处理/返回三段。
[NIT] 变量名 `tmp` 看不出用途，改成 `cacheKey`。
```

## 三、各语言高发检查项

**Python**
- 可变默认参数 `def f(items=[])`
- 裸 `except Exception` 吞掉所有错误
- 公开模块缺 `__all__`
- 同步阻塞调用卡在事件循环（如在异步函数里用 `requests`）

**TypeScript**
- 任意 `any` 类型绕过检查
- `async` 函数返回值没 `await`，rejection 未处理
- 可选链 `?.` 之后直接当非空用，缺空值兜底

**Go**
- 打开的文件/连接没 `defer` 关闭
- goroutine 泄漏（没退出通道）
- 错误被 `_` 吞掉不记录
- 锁粒度过大拖慢并发

**Java**
- 空指针未判（尤其外部入参）
- 资源（流、连接）未在 finally 关闭
- 异常被 catch 后不处理也不抛
- 过度 `synchronized` 造成死锁风险

**微信小程序**
- `setData` 传大对象或频繁调用卡渲染
- `onLoad` 里做重网络/重计算
- 缺骨架屏导致首屏白屏
- 滥用 `globalData` 存易变状态

## 四、不表演性同意决策树

```
收到一条反馈
├─ 能提升正确性 / 修掉真实 bug？
│   └─ 是 → 采纳并改，说明改了什么
├─ 只是风格偏好，却包装成原则？
│   └─ 是 → 说明你的不同意见，请对方确认再动，不默默照改
├─ 两条反馈互相矛盾？
│   └─ 是 → 把冲突摆出来，请作者判断，不替他二选一
└─ 置信度低、不确定是否真问题？
    └─ 标"疑似/建议确认"，不硬下结论制造噪音
```

核心：每条反馈按技术 merits 独立判断，不靠语气强弱决定采纳与否。

## 五、中文命名与 PR 描述检查

- 拼音缩写、中英混杂变量名（如 `usrList`、`getYhInfo`）→ `[SUGGEST]` 改中文语义清晰的名
- Pull Request 缺"改了什么 / 为什么 / 怎么验证" → `[BLOCK]` 补描述
- 评审意见对事不对人，用"这里的写法"而非"你这写法"
